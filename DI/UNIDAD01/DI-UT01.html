Arquitectura de la Información, Prototipado y Jerarquía Visual

Conceptos teóricos sobre la organización y estructuración de interfaces interactivas, técnicas participativas, feedback del sistema y el espectro de fidelidad en prototipos.

1.1 Arquitectura de la Información (AI) y Herramientas

Definición: Es el arte y la ciencia de estructurar, organizar y etiquetar sitios web, intranets, aplicaciones y software para apoyar activamente la usabilidad y la localizabilidad del contenido.

Objetivo primordial: Ayudar a las personas a encontrar datos y completar tareas con facilidad. Si el usuario no logra ubicar un elemento, para él carece de existencia.

Técnicas esenciales:
  • • Card Sorting: Método participativo donde los usuarios ordenan tarjetas temáticas en grupos intuitivos, determinando estructuras mentales y rotulados (abierto o cerrado).
  • • Mapas de Sitio (Sitemaps): Planos arquitectónicos jerárquicos que previenen duplicidades y ordenan la navegación antes de codificar.
// Ley de Fitts & Affordance

Affordance: Cualidad visual sugerente de uso. Un botón debe insinuar su accionamiento mediante sombras, relieves o bordes.

Ley de Fitts: El tiempo necesario para pulsar un objetivo depende de la distancia (D) y de su anchura (W).
→ Los botones críticos deben ser grandes y estar próximos al puntero o pulgar.

Feedback del sistema: Notifica continuamente al usuario el estado operativo mediante estímulos visuales, auditivos o hápticos.

1.2 El Espectro de Fidelidad del Prototipado

Fase 1 • Baja Fidelidad

Boceto (Sketching)

Lápiz y papel. Rápido, barato y desechable para explorar esquemas visuales iniciales sin distracciones estéticas.

Fase 2 • Media Fidelidad

Wireframe

El plano estructural en escala de grises. Utiliza cajas, textos simulados y marcas ("X") para reservar el espacio de contenidos.

Fase 3 • Alta Fidelidad

Mockup

Maqueta estática detallada con colores corporativos, tipografía real, iconografía definitiva y recursos visuales finales.

Fase 4 • Funcional

Prototipo Interactivo

Modelo digital interactivo con datos de ejemplo que simula clics, menús y transiciones antes de entrar en desarrollo software.

1.3 Las 4 Áreas de Trabajo en el Desarrollo de Interfaces

Área de Trabajo Responsabilidades y Funciones Agentes y Entregables
Área de Redacción Delimita los pilares funcionales y el objetivo del producto según el nicho de negocio. Definición de propósitos, flujos y contenidos funcionales.
Área de Producción Evalúa la viabilidad técnica y financiera, armonizando necesidades con plazos de desarrollo. Cliente, usuarios finales, estimación de presupuestos y calendarios.
Área Técnica Arquitectura e implementación técnica en lenguajes como Java, HTML, CSS o motores de base de datos. Programadores, responsables de sistemas y arquitectos software.
Área Artística Diseña la identidad visual (UI/UX), asegurando coherencia cromática, tipografías y estética. Diseñadores gráficos, paletas cromáticas, guías de estilo e iconos.

Gestores de Diseño (Layouts) y Patrón MVC en Java Swing

Organización espacial de componentes, control de redimensionamiento automático y separación estricta entre modelo de datos y vista visual.

Gestores de Diseño en Java Swing

Gestor de Diseño Estructura y Comportamiento Particularidad Técnica Caso de Uso Típico
BorderLayout Divide el contenedor en 5 áreas: NORTH, SOUTH, EAST, WEST y CENTER. La zona central absorbe el espacio sobrante. Layout predeterminado en contenedores de primer nivel (JFrame). Ventanas con barra de menús/botones superior e inferior y área de trabajo.
FlowLayout Dispone componentes secuencialmente de izquierda a derecha con salto automático de línea. Respeta el tamaño preferido (preferredSize) de cada componente. Botoneras horizontales simples o barras de herramientas.
GridLayout Cuadrícula estricta y simétrica configurada por filas y columnas. Todas las celdas comparten idénticas dimensiones forzando el redimensionamiento. Teclados numéricos, botoneras de calculadora o tableros de juego.
CardLayout Superpone paneles como una baraja donde solo uno es visible simultáneamente. Conmutación dinámica mediante identificadores de panel. Asistentes paso a paso (wizards) o navegación por pestañas.
Absolute (null) Desactiva el layout obligando a indicar coordenadas fijas $(x, y)$ y tamaño. Incompatible con diseño adaptable o redimensionado. Desaconsejado en proyectos de producción profesional.
Regla de oro: Una interfaz robusta se diseña anidando paneles simples con layouts específicos (por ejemplo, un contenedor exterior con BorderLayout que aloja paneles internos con GridLayout).

Arquitectura Modelo-Vista-Controlador (MVC) en Swing

1. Modelo (Model)

Almacén puro de datos (listas, colecciones, entidades). Notifica a las vistas cuando sufre alteraciones. Ejemplo: DefaultTableModel o DefaultListModel.

2. Vista (View)

Representación visual inerte sin lógica de negocio. Solo pinta píxeles consultando el modelo. Ejemplo: JTable, JList o JComboBox.

3. Controlador (Controller)

Gestores de eventos (ActionListener) que capturan la acción del usuario, operan sobre el modelo y refrescan la vista.

Principio de separación de Swing: Nunca se insertan o borran filas manipulando directamente el JTable; se opera sobre el Modelo y este propaga la actualización visual.

Lenguajes de Marcado XML y Heurísticas de Usabilidad

Comparativa entre diseño imperativo y declarativo, lenguajes derivados de XML y los 10 principios heurísticos de Jakob Nielsen.

Imperativo (Java) vs. Declarativo (XML)

Paradigma Imperativo (Java Swing)
  • • Instrucciones paso a paso escritas en código compilado.
  • • La lógica funcional y la definición visual se mezclan con frecuencia.
  • • Control exhaustivo de instanciación manual de componentes y layouts.
Paradigma Declarativo (XML / FXML / Android XML)
  • • Estructura visual jerárquica modelada mediante etiquetas de marcado legibles.
  • • Desacopla por completo la vista de la lógica de programación.
  • • El renderizado se delega al motor gráfico del entorno.

Las 10 Heurísticas de Usabilidad de Jakob Nielsen

1. Visibilidad del estado: Feedback continuo al usuario sobre lo que ocurre en tiempo razonable.
2. Relación con el mundo real: Utilizar el vocabulario y conceptos del usuario evitando códigos técnicos crípticos.
3. Control y libertad: Salidas de emergencia visibles (deshacer, cancelar, cerrar modal).
4. Consistencia y estándares: Mismos términos y acciones deben significar idéntica función en toda la app.
5. Prevención de errores: Diseñar interfaces que impidan cometer fallos antes de necesitar avisos.
6. Reconocimiento antes que recuerdo: Mantener visibles opciones y datos para reducir la carga cognitiva.
7. Flexibilidad y eficiencia: Aceleradores y atajos para usuarios expertos sin entorpecer a novatos.
8. Diseño minimalista: Evitar elementos irrelevantes que compitan con la información esencial.
9. Recuperación de errores: Mensajes claros que diagnostiquen el problema y propongan una solución constructiva.
10. Ayuda y documentación: Sección de asistencia concisa, estructurada y contextual a la tarea en curso.

import java.util.Random;

public class Personaje {
    private String nombre;
    private int fuerza, defensa, vida;

    public Personaje(String nombre) {
        this.nombre = nombre;
        Random rand = new Random();
        fuerza = rand.nextInt(8) + 3;
        defensa = rand.nextInt(6);
        vida = 10;
    }

    public boolean vivo() { return vida > 0; }
    
    public String ataca(Personaje defensor) {
        Random rand = new Random();
        if (rand.nextInt(100) < 70) {
            int danio = fuerza - defensor.defensa;
            if (danio < 1) danio = 1;
            defensor.vida -= danio;
            return nombre + " ataca a " + defensor.nombre + " y le quita " + danio + " de vida";
        }
        return nombre + " ataca pero falla el golpe";
    }
}

// Personaje abstracto
package logica;
public abstract class Personaje {
    private String nombre;
    private int fuerza;
    private int defensa;
    private int vida;
    private int vidaMax;

    public Personaje(String nombre, int fuerza, int defensa, int vida) {
        this.nombre = nombre;
        this.fuerza = fuerza;
        this.defensa = defensa;
        this.vida = vida;
    }
    
    public Personaje() {
        nombre = "";
        fuerza = 0;
        defensa = 0;
        vida = 0;
    }
    
    //Creo un constructor para poner la Fuerza-Defensa aleatorio y Vida sea 10
    public Personaje(String nombre) {
        this.nombre = nombre;
        Random rand = new Random();
        fuerza = rand.nextInt(8) + 3;
        defensa = rand.nextInt(6);
        vida = 10;
        vidaMax = 10;
    }

    public String getNombre() {
        return nombre;
    }

    public void setNombre(String nombre) {
        this.nombre = nombre;
    }

    public int getFuerza() {
        return fuerza;
    }

    public void setFuerza(int fuerza) {
        this.fuerza = fuerza;
    }

    public int getDefensa() {
        return defensa;
    }

    public void setDefensa(int defensa) {
        this.defensa = defensa;
    }

    public int getVida() {
        return vida;
    }

    public void setVida(int vida) {
        this.vida = vida;
    }

    public int getVidaMax() {
        return vidaMax;
    }

    public void setVidaMax(int vidaMax) {
        this.vidaMax = vidaMax;
    }

    @Override
    public String toString() {
        return nombre + " [Fuerza: " + fuerza + ", Defensa: " + defensa + ", Vida: " + vida + "]";
    }
    
    //Metodo que dice que true si es mas de 0 y false si es 0 o menos
    public boolean vivo() {
        return vida > 0;
    }

    public abstract String ataca (Personaje defensor);
    
    public int calcularDanio(Personaje defensor) {
        int danio = fuerza - defensor.getDefensa();
        return Math.max(danio, 1);
    }
}

// Subclase Guerrero
public class Guerrero extends Personaje {

    public Guerrero(String nombre) {
        super(nombre);
        setVida(15);
        setVidaMax(15);
        setDefensa(new Random().nextInt(3));
    }

    @Override
    public String ataca(Personaje defensor) {
        Random rand = new Random();
        if (rand.nextInt(100) < 75) {
            int danio = calcularDanio(defensor) + 1;
            defensor.setVida(defensor.getVida() - danio);
            return getNombre() + " (Guerrero) golpea con su espada a "
                 + defensor.getNombre() + " y le quita " + danio + " de vida";
        }
        return getNombre() + " (Guerrero) falla su espadazo";
    }
}

// Alumno.java
public class Alumno {
    private String nombre;
    private int edad;
    private double nota;

    public Alumno(String nombre, int edad, double nota) {
        this.nombre = nombre;
        this.edad = edad;
        this.nota = nota;
    }

    public String getNombre() { return nombre; }
    public int getEdad() { return edad; }
    public double getNota() { return nota; }

    public boolean aprobado() {
        return nota >= 5;
    }

    @Override
    public String toString() {
        return nombre + " (" + edad + " años) - Nota: " + nota
                + " - " + (aprobado() ? "Aprobado" : "Suspenso");
    }
}

// Atributos de la ventana
private JButton[] botones = new JButton[16];
private String[] simbolos = {
    "A","B","C","D","E","F","G","H",
    "A","B","C","D","E","F","G","H"
};
private int primera = -1;
private int parejas = 0;
private boolean bloqueado = false;

private void prepararTablero() {
    jPanelTablero.setLayout(new java.awt.GridLayout(4, 4, 5, 5));
    java.util.Collections.shuffle(java.util.Arrays.asList(simbolos));

    for (int i = 0; i < 16; i++) {
        final int posicion = i;
        botones[i] = new JButton("?");
        botones[i].addActionListener(e -> seleccionar(posicion));
        jPanelTablero.add(botones[i]);
    }
}

private void seleccionar(int posicion) {
    if (bloqueado || !botones[posicion].isEnabled()) return;

    botones[posicion].setText(simbolos[posicion]);

    if (primera == -1) {
        primera = posicion;
        return;
    }

    int segunda = posicion;
    if (simbolos[primera].equals(simbolos[segunda])) {
        botones[primera].setEnabled(false);
        botones[segunda].setEnabled(false);
        parejas++;
        primera = -1;

        if (parejas == 8) {
            JOptionPane.showMessageDialog(this, "¡Has encontrado todas las parejas!");
        }
    } else {
        bloqueado = true;
        // Pausa breve sin bloquear la interfaz
        javax.swing.Timer timer = new javax.swing.Timer(800, e -> {
            botones[primera].setText("?");
            botones[segunda].setText("?");
            primera = -1;
            bloqueado = false;
        });
        timer.setRepeats(false);
        timer.start();
    }
}

    private ArrayList<Pelicula> peliculas = new ArrayList<>();
    private String[] columnas = {"Título", "Director", "Año"};

    @Override
    public int getRowCount() { return peliculas.size(); }

    @Override
    public int getColumnCount() { return columnas.length; }

    @Override
    public String getColumnName(int columna) {
        return columnas[columna];
    }

    public Object getValueAt(int fila, int columna) {
        Pelicula p = peliculas.get(fila);
        switch (columna) {
            case 0: return p.getTitulo();
            case 1: return p.getDirector();
            case 2: return p.getAnio();
            default: return null;
        }
    }

        peliculas.add(p);
        fireTableDataChanged();
    }

private void jButtonEliminarActionPerformed(java.awt.event.ActionEvent evt) {
    int filaVista = jTable1.getSelectedRow();
    if (filaVista == -1) {
        JOptionPane.showMessageDialog(this, "Selecciona un contacto");
        return;

    int filaModelo = jTable1.convertRowIndexToModel(filaVista);
    int opcion = JOptionPane.showConfirmDialog(this, "¿Eliminar el contacto?",

        modelo.eliminar(filaModelo);

    private ArrayList<Astronauta> lista = new ArrayList<>();
    private String[] columnas = {"Nombre", "Misiones", "Edad", "Categoría"};

    @Override public int getRowCount() { return lista.size(); }
    @Override public int getColumnCount() { return columnas.length; }
    @Override public String getColumnName(int c) { return columnas[c]; }

    @Override
    public Object getValueAt(int fila, int columna) {
        Astronauta a = lista.get(fila);
        switch (columna) {
            case 0: return a.getNombre();
            case 1: return a.getMisiones();
            case 2: return a.getEdad();
            case 3: return a.getMisiones() >= 3 ? "Veterano" : "Aprendiz";
            default: return null;
        }

        lista.add(a);
        fireTableDataChanged();
